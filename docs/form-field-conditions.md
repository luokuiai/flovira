# 嵌套表单字段与流程条件

标准 `FormDefinition` 中，对象用 `fields` 描述具名子字段，
数组用 `items` 描述每个元素的类型。业务填写的数据仍保持原始嵌套结构，不需要展开成额外变量。

```json
{
  "schemaVersion": "1",
  "fields": [
    { "key": "address", "label": "地址", "dataType": "object", "fields": [
      { "key": "city", "label": "城市", "dataType": "string" }
    ] },
    { "key": "details", "label": "报销明细", "dataType": "array", "items": {
      "dataType": "object", "fields": [
        { "key": "amount", "label": "金额", "dataType": "number" },
        { "key": "category", "label": "费用类型", "dataType": "string" }
      ]
    } }
  ]
}
```

字段 `key` 是本层编码，支持英文字母、数字和下划线且不以数字开头；同层不能重复。
顶层不能使用表达式保留变量名 `this`、`root`。
`label` 必须填写业务名称。对象必须有非空 `fields`，数组必须有 `items`；数组元素本身
不需要 `key`、`label`，对象元素的子字段仍需提供。基础类型不能包含结构定义。
允许递归结构，深度限制为 32 层以拒绝循环和过深输入。

## 前端接入

Vue、React 均导出 `getFormConditionFields(formDefinition)`，接受标准对象或 JSON 字符串。
它只解析元数据，不根据填写值猜结构，也不会执行表单内容。

```ts
const fields = getFormConditionFields(formDefinition)
// React: <ReactFlowDesigner conditionFields={fields} />
// 或 queryConditionFields 中加载当前表单并返回 fields
// Vue: <FlowDesigner :condition-fields="fields" />
```

用户选择的是“地址 / 城市”“报销明细 / 每一项 / 金额”等名称；内部字段路径由组件生成。
字段数量/列表更新由宿主管理；字段被删除或类型改变后不能继续保存旧规则，需要重新选择。
Vue 在连线面板中点击“应用条件”后更新设计；React 使用已有“保存条件”入口。
未应用的面板修改不提交。已有表达式保留，不猜测其对应的可视化规则。

## 对象、汇总与明细组

- 对象：选择叶子字段，如“地址 / 城市 等于 上海”，不能比较整个对象。
- 汇总：当前提供“报销明细 / 数量”，可以判断空数组或条数。内部 `.$count` 是计算标记，
  不是业务数据中的字段。求和、平均值暂未内置，宿主可以提供具名计算字段。
- 明细：选择“报销明细”，再选“任一条 / 所有条满足以下全部条件”，然后添加组内字段条件。
  同一个组只判断同一条明细；不同组之间是“或”。普通字段和不同数组不能混入同一明细组。

例如“任一条：金额大于 5000 且费用类型等于差旅”，必须存在同一行同时满足两条条件。
第一行金额 6000 但类别为办公、第二行类别为差旅但金额 100，不满足这条规则。

空数组、缺失数组在任一条和所有条判断下均不满足；空行和缺失叶子字段也不匹配。
空数组的数量为 0，缺失数组不等同于空数组。
标准元数据可以递归描述多层数组，但当前明细组定位单个数组（可以位于对象内部），
不将跨多层数组的字段自动压平进行匹配；内层数组数量可以在外层明细组中判断。

默认编译为现有 `spel@@#{...}`，执行端需启用 Spring SpEL 插件，变量使用 JSON 对象/数组
对应的 Map / List（数字需为数值，布尔需为布尔）。表达式使用受限路径和基础比较，不放开方法或类型访问权限。
日期、日期时间目前作为字符串等值字段提供，宿主须统一格式；不做隐式日期转换。
运行时数据类型不匹配由现有表达式错误机制报告，不伪装成判断成功。

## 保存

`FormService.saveDefinition` 和标准定义读取会递归校验元数据；原始 `saveContent` 保留宿主
私有内容存储能力，不强迫所有渲染器采用标准格式。标准定义格式版本为 `1`。
私有格式应走原始内容接口，不应强行解析为标准定义。

不新增 SQL 列，不修改审批数据。可视化条件（包含名称、明细范围、匹配方式）保存于已有
节点 `ext.branchConditions`，与对应连线表达式一起往返；运行仍由连线表达式决定。
